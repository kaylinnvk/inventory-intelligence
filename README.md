# AI Inventory Intelligence

A data-driven inventory decision-support system built using the **M5 Forecasting dataset**.

The project analyzes historical retail demand, forecasts future product sales, and converts those forecasts into actionable inventory recommendations through an interactive Streamlit dashboard.

---

## Problem

Retailers need to balance two major inventory risks:

* **Stockouts** — insufficient inventory can lead to lost sales and poor customer experience.
* **Overstock** — excessive inventory increases storage, holding, and operational costs.

The goal of this project is to use historical sales, pricing, calendar, event, and SNAP information to better understand demand patterns and support inventory decisions.

---

## Proposed Solution

The project follows this pipeline:

```text
Historical Sales + Price + Calendar Data
                    ↓
            Data Preparation
                    ↓
          Exploratory Analysis
                    ↓
           Demand Forecasting
                    ↓
        Inventory Risk Analysis
                    ↓
        Reorder Recommendations
                    ↓
          Streamlit Dashboard
```

The final system is intended to help users answer questions such as:

* How is demand changing over time?
* Which stores, departments, and products have the highest demand?
* How do weekends, events, and SNAP days relate to demand?
* What is the expected demand for a product over the next 28 days?
* Which products may be at risk of stockout or overstock?
* How much inventory should be reordered?

## Dataset

This project uses the **M5 Forecasting dataset**, which contains historical Walmart retail sales data.

The main source tables include:

* `sales_train_validation.csv`

  * Daily unit sales by product and store
* `calendar.csv`

  * Dates, weekdays, events, and SNAP information
* `sell_prices.csv`

  * Weekly selling prices for each product-store combination

### Current Project Scope

The current prototype focuses on the `FOODS` category across three stores:

* `CA_1`
* `TX_1`
* `WI_1`

The selected dataset contains approximately:

* **1,437 unique products**
* **3 stores**
* **4,311 product-store time series**
* **1,913 days of historical sales**
* **8.2 million product-store-day observations**

Large raw and processed datasets are not committed to this repository.

## Dashboard

The project uses **Streamlit** to provide an interactive interface for exploring demand, forecasts, and inventory recommendations.

The dashboard is divided into four main sections.

### 1. Overview

Provides a high-level view of historical demand.

Planned components include:

* Total units sold
* Average daily demand
* Number of products
* Number of stores
* Historical demand trend
* Sales by store
* Sales by department
* Weekday demand
* Weekend effect
* SNAP effect
* Event effect

---

### 2. Product Explorer

Allows users to explore individual products.

Users can filter by:

```text
Store
Department
Product
```

The page can display:

* Historical product demand
* Average daily demand
* Total units sold
* Maximum daily sales
* Price history
* Weekday demand pattern
* Event effects
* SNAP effects

---

### 3. Demand Forecast

Displays future demand predictions generated by the forecasting model.

The initial forecasting horizon is:

```text
28 days
```

The dashboard expects forecasting output in a standardized format such as:

```text
item_id
store_id
date
predicted_sales
```

Example:

| item_id     | store_id | date       | predicted_sales |
| ----------- | -------- | ---------- | --------------: |
| FOODS_3_090 | CA_1     | 2016-04-25 |            67.2 |
| FOODS_3_090 | CA_1     | 2016-04-26 |            63.8 |
| FOODS_3_090 | CA_1     | 2016-04-27 |            71.3 |

This allows the forecasting model to be developed independently from the dashboard.

---

### 4. Inventory Recommendations

Forecast results are converted into inventory-related recommendations.

Possible outputs include:

* Expected demand
* Inventory risk level
* Stockout risk
* Overstock risk
* Suggested reorder quantity
* Suggested reorder timing
* Product-level recommendation

The expected integration format may include:

```text
item_id
store_id
forecast_demand
reorder_quantity
risk_level
recommendation
```

## Data Management

Large datasets should **not** be committed to GitHub.

The repository `.gitignore` excludes:

* Raw datasets
* Large processed datasets
* Virtual environments
* Model artifacts
* Secret files
* Temporary files

Processed dashboard data should normally be stored locally under:

```text
data/processed/
```

Parquet is preferred over CSV for large processed datasets because it is more compact and faster to load.

Example:

```python
df.to_parquet(
    "data/processed/dashboard_data.parquet",
    index=False
)
```
